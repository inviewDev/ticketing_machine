# 티켓팅 도우미

React + Vite 화면과 로컬 Node.js/Playwright 실행기로 구성한 Windows 티켓팅 보조 프로그램입니다. 기존에 잘못 만든 ONSTAGE 판매 사이트와 분리된 프로젝트입니다.

## 실행

상위 폴더의 **프로그램 실행.cmd**를 더블클릭합니다. 설치된 Chrome을 사용해 프로그램 화면과 티켓처 창을 엽니다. 실행 창을 닫으면 프로그램이 종료됩니다. 프로그램이 이미 실행 중일 때 다시 더블클릭하면 새 서버를 중복 실행하지 않고 기존 화면을 엽니다.

Edge로 비교해야 할 때는 실행 중인 검은 창을 먼저 닫고 **Edge로 실행.cmd**를 사용합니다. 두 실행 파일 모두 Windows에서 불필요한 `--no-sandbox` 플래그를 제외합니다. 브라우저 변경은 호환성 확인용이며 티켓처의 접근 제한이나 보안 확인을 우회하지 않습니다.

```powershell
cd ticket-assistant
npm install
npm run browser:install
npm run dev
```

화면: http://127.0.0.1:5174/ (다른 프로그램과의 포트 충돌을 피하기 위해 5174 사용)

프로덕션 실행: `npm run build` 후 `npm start` → http://127.0.0.1:4318/

## 사용 순서

1. 멜론티켓 / NOL 티켓 / YES24 / 샤롯데씨어터 / 세종문화회관을 단일 또는 다중 선택합니다.
2. 티켓처를 선택하면 해당 사이트의 전용 브라우저가 열립니다. 로그인을 직접 진행합니다.
3. 로그인 연결에서 상태를 확인합니다. 공식 티켓처 화면의 **보이는 로그아웃 메뉴**를 확인한 경우에만 로그인 확인됨으로 표시합니다. 이전 탭의 표시나 SSO 서비스의 로그인만으로 성공을 표시하지 않습니다. **새로 확인**은 별도 확인 탭에서 공식 페이지를 갱신합니다. 계정 메뉴를 열어야 로그아웃이 보이면 갱신된 창에서 메뉴를 열고 자동 확인을 기다립니다.
4. 티켓처별 실제 공연 URL을 입력하고 입력란에서 나오면 공개 상세 페이지를 자동 확인합니다. **공연 정보 확인**으로 다시 읽을 수도 있습니다. 결과 카드에는 공식 페이지에서 읽은 작품명, 공연장, 최종 확인 주소와 확인 시각이 표시됩니다. 등록된 공연장이면 기준 배치도를 표시하고, 자동 판별이 안 되면 공연장을 직접 선택합니다. 수동으로 고른 공연장은 늦게 도착한 자동 결과가 덮어쓰지 않습니다.
5. 관람 날짜를 고르면 연결된 공식 공연 페이지에서 그날의 실제 회차와 캐스팅을 불러옵니다. 멜론 오픈 전이라 선택 영역이 없다면 멜론티켓만 선택하고 **회차 입력 방식 → 멜론 오픈 전 회차 직접 입력**으로 바꿉니다. 공지에 나온 관람 날짜·회차 시간을 직접 입력하고, **예약 실행**에는 티켓 오픈 시각을 입력합니다. 실제 회차를 불러오지 못해도 예약할 수 있으며 오픈 후 입력한 날짜·시간과 일치하는 공식 버튼만 선택합니다. 다른 티켓처의 회차 지원 범위는 아래 검증 기록을 참고하세요.
6. 조건을 설정하고 로그인 확인이 완료되면 실행할 수 있습니다. 예약 실행은 **PC 시계의 한국 시간** 기준이며 프로그램과 PC가 켜져 있어야 합니다. 5분 전에 로그인과 공연 페이지를 준비합니다. 날짜·회차가 있으면 미리 선택하고, 없으면 실패로 끝내지 않고 남은 시간을 표시하며 오픈 대기로 유지합니다. 멜론은 정각에 기존 화면부터 확인하고 필요할 때만 **2초 이상 간격, 최대 10회, 오픈 후 60초 이내**로 공연 페이지를 갱신합니다. 갱신 후에는 날짜부터 다시 선택합니다. 제한에 도달하면 현재 창에서 이어갈 수 있도록 멈춥니다. 다른 티켓처는 기존의 정각 1회 갱신 방식을 유지합니다.
7. 선택한 티켓처들을 함께 진행하고 한 곳에서 좌석을 클릭하기 시작하면 다른 곳의 추가 클릭을 멈춥니다. 로그인·보안 확인·결제는 직접 처리합니다. 좌석 클릭 후 상태를 읽지 못하면 성공 대신 직접 확인 필요로 표시합니다.
8. 로그인·보안 확인이나 찾지 못한 항목 때문에 멈추면, **실행 기록 → 화면 보기**에서 직접 진행합니다. 이어갈 단계를 골라 **이 단계부터 이어가기**를 누르면 같은 예매창을 사용합니다. 예를 들어 날짜를 직접 선택했다면 회차 선택부터 이어갑니다. 좌석을 클릭한 뒤에는 자동 이어가기를 제공하지 않습니다.

멜론 오픈 재탐색은 예매 버튼을 클릭하기 전까지만 적용됩니다. 예매 클릭 후 응답을 읽지 못해도 재클릭하거나 새로고침하지 않습니다. 감지된 공식 대기열·보안문자·로그인·접근 제한에서는 자동 갱신을 멈추고 화면을 유지합니다. 대기열 통과나 직접 인증 후에는 현재 단계부터 이어가기를 누릅니다. 서버 시각 동기화나 티켓 선점 보장은 제공하지 않습니다.

2026-09-22 오픈 흐름 검증: 실제 Chromium의 모의 카운트다운에서 지연 오픈·화면 자체 전환·대기열 진입, 날짜 선택 초기화 후 재선택, 갱신 제한·중지, 오픈 전 회차 입력·저장·예약 대기 UI를 검증했습니다. 실사이트 오픈 경쟁과 실제 좌석 선점은 별도 검증이 필요합니다. 업데이트 후 기존 실행 창을 닫고 **프로그램 실행.cmd**로 다시 실행합니다.

로그인 상태는 보이는 화면을 주기적으로 읽습니다. NOL 마이페이지의 공식 로그인 응답은 메인·공연 화면으로 이동해도 같은 브라우저 세션에서 유지합니다. **새로 확인**과 실행 직전에는 이전 응답을 버리고 마이페이지에서 다시 검증합니다. 바로 갱신한 확인 탭은 30초 이내에 한해 재사용하되 표시를 다시 읽습니다. 서버 측 세션 유효성을 보장하는 공식 인증 API 검증은 아닙니다. 숨겨진 메뉴나 사이트의 화면 구조 때문에 판정할 수 없으면 미확인으로 남습니다.

YES24가 전용 자동화 브라우저를 `Code 12`로 제한하면 프로그램에서 **접근 제한됨**으로 표시합니다. 이는 사용자가 처리할 수 있는 보안문자 상태가 아니며 프로그램이 제한을 우회하지 않습니다. 2026-09-11 기준 정식 Chrome과 Edge의 앱 세션 모두 같은 제한을 받았습니다.

## 공연장 좌석도에서 희망 좌석 선택

공연장 좌석도는 티켓처와 분리되어 있습니다. 같은 공연장이면 멜론티켓·NOL 티켓·YES24 등 어느 판매처의 공연이든 같은 기준 배치도를 사용합니다.

1. **공연장에서 좌석도 찾기**는 입력한 공식 공연 상세 페이지의 공개 HTML에서 공연 제목과 공연장 이름만 확인합니다. 로그인 창, 보안인증 창, 예매 팝업을 열거나 좌석을 클릭하지 않습니다.
2. 자동 판별이 안 되면 공연장 목록에서 직접 선택할 수 있습니다. 현재 블루스퀘어 우리은행홀, 디큐브 링크아트센터 디큐브씨어터, 광림아트센터 BBCH홀, 샤롯데씨어터, 예술의전당 CJ 토월극장·오페라극장, 충무아트센터 대극장, 코엑스아티움 우리은행홀, 홍익대 대학로 아트센터 대극장, LG아트센터 서울 LG SIGNATURE 홀, 세종대극장, 링크아트센터 PAYCO홀·BUGS홀을 제공합니다.
3. 층을 고른 뒤 좌석을 직접 누르거나 열 버튼으로 한 번에 선택합니다. 선택 순서가 우선순위가 되며 티켓처별 최대 1,000석까지 지정할 수 있습니다. 키보드 Tab과 Enter/Space도 지원합니다.
4. **설정 저장**으로 선택을 보관합니다. 선택은 티켓처·공연 URL·공연장에 연결됩니다. 날짜·회차를 바꿔도 같은 공연과 공연장이면 유지되며, 공연 URL이나 공연장을 바꾸면 해당 선택을 지웁니다.
5. **좌석 선택 실행**은 공식 예매창의 현재 잔여 좌석 중 저장된 층·구역·열·번호와 일치하는 좌석만 시도합니다. 일치하지 않으면 다른 좌석을 추측하지 않습니다. 연석은 같은 구역·열의 연속 번호로 판단합니다.

기준 좌석도에는 공연별 OP석, 통제석, 시야제한석, 휠체어석 변경이 반영되지 않을 수 있습니다. `공식 기본 좌석도 반영` 공연장은 공식 도면의 일반 좌석 표기를 옮겼고, `공식 자료 기반 단순 도면` 공연장은 층·구역·좌석 수를 단순화했습니다. 실제 예매 시에는 공식 좌석창의 표기가 최종 기준입니다.

## 보안문자 인증 후 이어가기

멜론의 ‘인증예매’처럼 보안문자 입력창이 감지되면 추가 클릭을 멈추고 해당 예매창을 앞으로 표시합니다. 실행 기록에는 **보안인증 대기**와 **인증 화면 보기**, **인증 완료 후 이어가기**가 표시됩니다.

1. 공식 예매창에서 보안문자를 직접 입력하고 **입력완료**를 누릅니다.
2. 프로그램에서 **인증 완료 후 이어가기**를 누릅니다. 인증만 완료했다면 기본으로 선택된 중단 단계를 유지하면 됩니다.
3. 같은 예매창의 보안 상태를 다시 확인합니다. 인증창이 남아 있으면 다시 대기하고 좌석을 클릭하지 않습니다. 인증이 완료되면 선택한 단계부터 진행합니다.

인증 문자·인증번호는 프로그램에서 읽거나 저장하지 않습니다. 자동 해독, 자동 입력, 보안인증 우회 기능은 없습니다. 중지 버튼을 누른 실행이나 이미 좌석을 클릭한 실행은 자동으로 재개하지 않습니다. 로그인 후 공연 상세 화면으로 돌아왔다면 이어갈 단계에서 **예매하기**를 다시 선택할 수 있습니다.

2026-09-11 검증: 모듈/API 93개, 실제 Chromium 모의 화면 테스트 22개, 앱·API·실행기를 연결한 UI 통합 테스트 1개, 구문 검사·빌드 통과. 공연장 자동 판별·직접 선택, 12개 공연장 좌석도, 공식 회차 선택과 캐스팅 표시, 날짜·회차와 독립된 희망 좌석, 저장·복원, 모바일·키보드 선택, API 출처·토큰·리디렉션 제한을 확인했습니다. NOL 실페이지 예약 점검에서는 지정 시각 전에 날짜·회차를 선택한 채 대기하고, 지정 시각에 같은 탭에서 예매 단계로 진입하는 것도 확인했습니다. 이 결과가 모든 티켓처의 최신 화면에서 동작한다는 보장은 아닙니다.

- 멜론 날짜·회차·예매 버튼에는 전용 탐색을 적용합니다. 날짜 목록과 회차의 동일한 날짜 속성을 구분하고, 달력에 없는 날짜는 목록 보기로 전환합니다. `19시 30분`과 출연진이 함께 표시된 버튼도 시간 부분을 비교합니다. `accounts.melon.com`의 로그인 화면을 인식합니다. 사용자 지정 화면 연결 값은 전용 탐색보다 우선합니다.
- **NOL은 사용자가 로그인한 실제 계정의 마이페이지 응답까지 확인했습니다. 다른 티켓처의 실계정 로그인과 실공연 좌석 선택·서버 선점은 아직 검증하지 않았습니다.** 로컬 브라우저 테스트는 실제 Chromium에서 모의 날짜·회차·좌석 화면을 클릭하며 실계정 예매 성공을 뜻하지 않습니다.
- 좌석 선택과 다른 티켓처는 공식 도메인의 DOM 항목을 이용하는 공통 엔진입니다. 모든 공연에 대해 동작이 검증된 전용 어댑터가 아닙니다. 구역은 정확한 구역명으로 찾으며 선호 열은 입력한 순서대로 비교합니다. 실제 공연 화면에 맞춘 연결과 실동작 확인이 필요합니다.
- 좌석에 구역·열·번호 정보가 없거나 좌석도가 캔버스인 경우 자동 선택을 중단합니다. 대기열 우회, 보안문자 처리, 자동 결제 기능은 없습니다. 좌석 클릭과 서버 선점·결제 완료는 다른 상태입니다.

## 공연별 화면 연결

화면 연결 메뉴에서 예매하기, 날짜, 회차, 구역, 좌석의 Playwright/CSS 선택자를 지정할 수 있습니다. 기본 자동 탐색으로 읽히지 않는 공연을 연결하기 위한 고급 설정입니다. 실제 페이지에서 확인한 항목만 사용합니다.

직접 지정한 선택자는 기본 탐색보다 우선하며, 해당 항목이 없다고 다른 버튼을 대신 누르지 않습니다. 항목이 늦게 나타나면 최대 6초 동안 화면을 읽어 기다립니다. 이 과정에서 페이지를 반복 새로고침하지 않습니다.

- 날짜: `{date}` → `2026-10-17`, `{dateCompact}` → `20261017`, `{day}` → `17`
- 회차: `{time}` → `19:00`
- 구역: `{zone}` → 현재 선호 구역
- 예: `[data-date="{date}"]`, `[data-time="{time}"]`, `[data-zone="{zone}"]`
- 좌석은 `title`/`aria-label`의 `1층 A구역 3열 12번`, 또는 `data-zone`, `data-row`, `data-seat-no` 속성으로 해석합니다.
- 선택 결과는 `aria-selected`, `aria-pressed`, `data-selected`, `selected`/`on` 클래스 등을 읽습니다. 확인할 수 없으면 직접 확인 필요 상태로 멈춥니다.

## 파일과 개인정보

- `src/`: React 사용자 화면
- `shared/`: 티켓처 정의, 설정 검증, 로그인 판정, 좌석 조건
- `server/`: 로컬 API, 전용 브라우저 관리, 예매 실행기
- `tests/`: 모듈/API 테스트 (실계정 로그인 테스트 아님)
- 로그인 프로필: `%LOCALAPPDATA%\TicketAssistant\profiles\<티켓처>`
- 저장 설정: `%LOCALAPPDATA%\TicketAssistant\settings.json`
- 로그인 정보는 OneDrive 작업 폴더로 복사하지 않습니다. 브라우저 프로필을 공유하지 마세요.
- API는 루프백 주소에만 바인딩하고 프로그램 토큰 및 요청 출처를 검사합니다.

## 검증 명령

```powershell
npm run check
npm test
npm run test:browser
npm run test:ui
npm run build
npm run probe
```

`probe`는 공개 홈페이지 접속 검사이며 로그인 성공 여부를 검사하지 않습니다. 결과는 `.local/connectivity.json`에 저장됩니다.

`test:browser`는 설치된 Chromium을 이용하며 모든 네트워크 요청을 테스트 화면으로 대체합니다. 실제 사이트에 예매 요청을 보내지 않습니다.

`test:ui`는 프로덕션 화면을 빌드하고 실제 로컬 API·실행기와 연결해 5개 티켓처에서 공연장 판별과 희망 좌석 저장을 확인합니다. 외부 티켓처 요청은 모의 응답으로 대체합니다. 데스크톱·모바일 캡처는 `.local/audit/venue-map-desktop.png`, `.local/audit/venue-map-mobile.png`에 저장합니다.
